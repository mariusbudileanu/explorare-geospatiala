Ce înseamnă interoperabilitate?

O extensie de fișier comună nu garantează singură interoperabilitatea perfectă. Contează specificația, suportul software, CRS-ul, metadatele, tipurile de câmpuri și geometrii, versiunile, extensiile și convențiile.

Verifică după schimb: numărul de features / celule, câmpurile, CRS-ul și sensul variabilelor. Containerul, encoding-ul și infrastructura de acces au roluri diferite.

Fișiere asociateShapefile → .shp + .shx + .dbf + .prj
ContainerGeoPackage → SQLite + reguli OGC
TextGeoJSON → JSON pentru features
Raster binarGeoTIFF / COG → TIFF + georeferențiere
Model științificNetCDF → array-uri, encodings și convenții; frecvent fișiere / colecții
Store cu chunksZarr → metadata + obiecte adresabile; filesystem sau stocare distribuită

GeoParquet poate organiza un fișier sau un dataset columnar. Organizarea fizică și specificația trebuie interpretate împreună.

Alte formate pe care le vei întâlni

  • CSV — tabel text care poate conține coordonate.
  • GML — encoding XML geospațial.
  • KML — schimb și vizualizare în ecosistemul Earth.
  • SpatiaLite — extensie spațială pentru baze SQLite.
  • MBTiles — container SQLite pentru tiles.
  • HDF5 — container științific ierarhic, relevant și pentru NetCDF-4.
  • LAS/LAZ — nori de puncte, cu variantă comprimată.

Ce simulează laboratorul?

Scene originale, sintetice și deterministe. Nu parsează fișiere reale și nu execută query-uri, Range requests sau cereri către un object store. Cuburile NetCDF și Zarr explică un model mental.

Performanțele reale depind de implementare, compresie, index, server și pattern-ul de acces. Formatul potrivit păstrează informația necesară și se potrivește fluxului de lucru.

5. DATE GEOSPAȚIALE · Laborator L10

Experimente de stocare și acces

Compară schimbul unui vector mic, subsetarea unui raster și un cub temporal. Volumul util, obiectele necesare și read amplification sunt mărimi distincte.

Metodă și limite

Model ipotetic necomprimat: raster 6×6, cub 6×6×6, float32 de 4 bytes, tiles 2×2 și chunks 2×2×2. Metadatele, compresia și overhead-ul HTTP sunt excluse. Bytes modelați / bytes utili exprimă amplificarea citirii; traficul real al experimentului este zero. Nu este benchmark și nu se interoghează S3 sau EOCube.

F5 și F6 rămân explicațiile pentru cuburi. L12 Zarr este disponibil separat, cu snapshot offline și acces modelat.
